BEFUNDE:
  1. FFT nutzt FFTW_ESTIMATE (fft-handler.cpp:45)
     -> Schnellste Plan-Erstellung, LANGSAMSTE Ausfuehrung!
     -> FFTW_MEASURE oder FFTW_PATIENT waeren deutlich schneller
     -> Wisdom-Persistierung wuerde Startup-Kosten von MEASURE eliminieren

  2. Unnoetige Datenkopien in fft() (fft-handler.cpp:59-89)
     -> Jeder FFT-Aufruf: memcpy rein + memcpy raus (2x 2048 Complex = 32KB)
     -> Bei 76 Symbolen/Frame: 152 unnoetige Kopien pro Frame (~96ms)
     -> Loesung: In-Place FFT mit fftwf_execute_dft() direkt auf Eingabedaten

  3. Default-Decoder ist DECODER_3 (ofdm-handler.cpp:103)
     -> Einfachster Decoder, keine Rauschschaetzung/Gewichtung
     -> decoder_12 (DECODER_1/2) nutzt SigmaSQ-Gewichtung fuer bessere Soft-Bits
     -> decoder_4 nutzt Bessel-LLR (optimal, aber CPU-intensivster)
     -> Empfehlung: DECODER_1 als Default testen (bester Kompromiss)

  4. Soft-Bit-Erzeugung komplett skalar (ofdm-decoder.cpp:437-605)
     -> Carrier-Schleife: 1536 Iterationen, keine SIMD-Nutzung
     -> Pro Carrier: normalize(), conj(), Multiplikation, toQ1() -- alles skalar
     -> Potenzial: SSE/AVX koennte 4-8 Carrier parallel verarbeiten

  5. estimator wird JEDES MAL neu instanziiert (ofdm-handler.cpp:699)
     -> generate_CI() erstellt lokalen estimator mit 2 neuen FFT-Instanzen
     -> FFTW Plan-Erstellung ist teuer (auch bei ESTIMATE: ~1ms pro Plan)
     -> Loesung: estimator als Member von ofdmHandler, einmalig erstellen

  6. Clock-Error-Korrektur vorbereitet aber NICHT aktiv
     -> decoder_3 (Zeile 499): phaseBase berechnet, nie angewandt
     -> decoder_12 (Zeile 418-488): clockError Parameter ungenutzt
     -> Aktivierung koennte Empfang bei billigen RTL-SDR Sticks verbessern

  7. Bessel-Tabelle (decoder_4) ist global und fest (besselTable[2048])
     -> Aufloesung: x*32, Modulo 2048 -> max x=64
     -> Fuer Signale mit hohem SNR evtl. zu grob

STUFE 10b: MP4/AAC-AUDIO (DAB+)
================================================================================
--- Analyse (2026-03-30) ---
Reed-Solomon: Galois-Feld mit Lookup-Tables (alpha_to/index_of), L1-Cache-freundlich.
  Berlekamp-Massey + Chien-Search, Standard-Algorithmus. Kein Optimierungsbedarf.
Bit-Packing: ~384 Bytes/Frame, vernachlaessigbar.
AAC-Decoder: FAAD2 war aktiv, FDK-AAC verfuegbar aber nicht installiert/aktiviert.

--- Optimierung ---
[x] OPT-10b.1: FDK-AAC statt FAAD2 aktiviert
     - Paket mingw-w64-ucrt-x86_64-fdk-aac installiert
     - CMakeLists.txt: FDK_AAC=ON, Include-Pfad korrigiert
     - libfdk-aac-2.dll nach C:/dab-build/ kopiert
     - Build + Funktionstest erfolgreich

Vorteile FDK-AAC gegenueber FAAD2:
  - Bessere HE-AAC v2 Unterstuetzung (SBR + PS)
  - Geringere CPU-Last
  - Bessere Audio-Qualitaet bei niedrigen Bitraten
  - Aktiv gewartet (Fraunhofer)
